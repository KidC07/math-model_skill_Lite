# 交付与环境

## 当次比赛规则

仅用于竞赛时确认官方赛事名称、届次、赛道和阶段，不将某一赛事规则用于一般建模项目。不同赛事、赛道和阶段的要求不能相互替代；以本次官方题面、参赛手册、通知与提交模板为依据，记录来源和查阅日期。

规则未取得时继续处理不依赖它的建模和证据，不虚构论文页数、匿名要求、AI 使用许可或评奖规则。格式预设只能标为工作方案；正式提交前补齐会影响提交有效性的官方要求。AI 使用记录如实维护，按当届要求披露，不进行规避检测的处理。

## 本机已有工具

用户要求由 Agent 配置环境时，按根目录 [Agent 环境配置指南](../../../../Agent环境配置指南.md) 完成检测、必要补缺、编辑器配置和实际验收；只读或普通写作任务不自动触发安装。已授权的配置任务自主完成范围内操作，无需为同一授权重复确认。

首次运行或环境变化时，使用本包 `scripts/local_check.py check` 检查当前任务所需能力；默认包括 LaTeX。根目录 `快速检查.py` 用明确标记的合成数据实际验证计算、读写、绘图及中文 LaTeX 编译；不读取赛题，不修改既有环境。自检文件仅运行时生成，不预置在交付包中。

选择已有 Python 可通过根目录 `启动检查.ps1 -Python <已有解释器>`，或直接用该解释器运行脚本。根目录可选的 `本机环境.json` 只提供现有解释器候选路径；不存在或能力不足的候选会被跳过。队友可换为自己的路径，不能依赖开发者电脑目录。包内相对路径不能改成个人绝对路径。

缺少能力时先核对当前解释器与已有工具。确需安装且用户已授权时，只补相应依赖；未经授权不安装，不重建已有环境。根目录 requirements.txt 是新电脑的基础库清单，绘图统一用 Matplotlib + Seaborn。缺少数值库不能凭空声称已经求解。

工具报告“拒绝访问”或 DLL 加载失败时，区分包缺失、解释器选择、二进制兼容性和执行隔离。可先让同一解释器在已有终端做只读导入检查，或按宿主权限机制申请范围明确的执行许可；不要把隔离失败直接写成“本机未安装”，也不要因此改环境。

## LaTeX 编写与预览

论文统一采用 LaTeX，不生成 `.doc` 或 `.docx`。每台电脑都需能编辑 `.tex`、编译、预览 PDF。共享源文件使用 UTF-8、相对路径和可获得的字体，图表及实际使用的 `.bib` 随源文件交接。

新电脑采用 VS Code + LaTeX Workshop + TinyTeX（XeLaTeX）；已有可用 TeX 安装继续使用。包内 `.vscode/settings.json` 明确配置 XeLaTeX 两遍编译及内置 PDF 预览，手动构建，不依赖 latexmk/Perl。把设置用于新项目时保留原有配置；已有工程采用经验证的编译流程。文献由 BibTeX/Biber 管理时，按实际项目补上相应编译步骤，核对引用而非盲目多编译几遍。

在 Codex 中创建或编辑独立 LaTeX 文档时优先内置编辑器和编译工具；多人共享的本地工程还应按上述 VS Code 路线验证。检查最终 PDF 的页面、公式、图表、交叉引用与字体，修复编译错误及影响阅读的警告。缺包只在获得安装授权后补齐，不依靠编译时静默下载。

## 截止前保护交付

尽早试通本次需要的导出链路，保持一份可以恢复的已验证版本。剩余时间不足时先处理漏答、不可行、数据泄漏、数字冲突和官方提交要求，再处理局部美观。修改后只重跑受影响的验证。

提交前先对照题目确认每问有明确答案、关键选择有理由、主要判断有证据；检查摘要、主图与结论是否突出这些内容。常规检验简述，影响推荐的失败必须进入相关正文。随后核对数值、引用、匿名与官方声明，实际打开论文和题目规定文件检查页面、公式与附件。

提交包使用相对路径，包含真实依赖说明、运行入口和必要结果。不要把缓存、虚拟环境、私人配置或无关材料放入提交包。

本包用于准备文件；外部上传、消息发送或替用户提交须有对应授权。交付时准确区分完成、已验证和仍需人工或官方确认的事项。
