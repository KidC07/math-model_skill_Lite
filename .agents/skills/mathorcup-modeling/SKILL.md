# 数学建模通用 Skill

目标是形成回答题目、有洞察、可复现且便于评阅的作品。让读者看清本文的答案、关键选择和证据。验证深度由结论风险决定，正文篇幅由论证价值决定；不因少写验证而少做核验。常规可逆实现、低成本实验和文稿改写自主推进；缺失的价值偏好、实质题意歧义或授权边界才需要用户决定。

## 开始与继续

先区分完整建模项目、接手已有项目和局部任务。读取本次材料及已有结果，确认问题之间的依赖、可用时间、交付要求与当前最有价值的下一步；竞赛项目再核对当次官方规则。完整项目尽早形成可运行基线和可打开的论文样稿，已有项目沿用真实结构。局部任务只读取必要上下文。

只有需要长期接续时，维护一份简短项目记录：各问当前答案和结果位置、关键假设、已做实验、未解决事项及下一步。它是索引；数字仍以实际结果文件为准，不建立重复的多层状态表。

本包不依赖其他 Skill 或原始参考仓库。根目录的 `使用说明.md` 提供入口；首次计算或环境变化时按需运行 `scripts/local_check.py`。路径相对本文件解析，所有赛题产物写入用户项目。复用现有环境；确有缺项且用户已授权时，只补必要依赖，不顺带升级环境。

论文统一用 LaTeX，交付可编辑源文件、所需素材及编译后的 PDF，不生成 Word 文稿。每位使用者的环境均需支持编辑、编译与预览，按 [交付与环境](references/delivery.md) 核验。

## 推进方式

- **理解与探索**：明确对象、参数定义、量纲、观测与决策时点、评价口径。能改变答案的解释差异先做小例子或对照；未确定的解释标为工作假设。候选方案来自问题结构，不固定模型数量，不预先排斥机器学习或复杂方法。题目专属参数和领域解释写在项目中。
- **基线与改进**：先建立并验收基线，再正式比较改进。验收覆盖题意适配、数学与实现一致性、独立复算及当前数据的必要约束；旧模板也需核验。按需用 [基线方法库](references/baselines.md)，只读当前候选对应的指南。保留已验收基线，在公平口径下按有效性、解释力和代价选方案；实验设计读 [实验与判断](references/experiments.md)。
- **论文与图形**：尽早形成论证草稿，与实验相互反馈。以证据支持的判断组织每问，解释方法选择、结果含义和实际价值；可以重写章节与图文结构。证据充分时直接陈述，关键条件在相关位置交代，不用层层自我否定代替判断。写作时读 [表达与绘图](references/expression.md)；出图时读 [绘图工具](references/figures.md)，使用 Matplotlib + Seaborn 及包内绘图辅助函数。
- **核验与交付**：正式采用结果前主动核对题意、比较口径、可行性和关键数值，并完成支撑主要主张的验证。常规通过项简述，决定结论的检验展开；影响推荐的失败必须处理或明确改变结论。修改后只复核受影响部分，提交前检查规则和实际页面。按需读 [交付与环境](references/delivery.md)。

## 四种职能，按需协作

主 Agent 统筹建模手、编程手、写作手和评委四种职能，依据任务规模合并承担或委派；局部任务只启用相关职能，不固定启动四个代理，也不要求每步轮流会签。

| 职能 | 对结果负责的重点 |
|---|---|
| 建模手 | 解释题意，确定变量、假设、目标与约束，建立可验收基线；提出改进及可检验的收益判据，模型变化同步实现与论文。 |
| 编程手 | 将模型落实为真实计算，核对数据接口、数值结果和可复现性；发现定义或约束冲突时反馈建模，不能为跑通代码悄悄改题。 |
| 写作手 | 从建模早期组织问题、观点与证据，反向提出值得补的实验；形成有重点的图文和 LaTeX 文稿，结论与实际证据同步。 |
| 评委 | 依据本次问题与交付要求，检查是否答题、基线是否可信、改进是否有价值、观点是否讲清；指出最影响结论或评阅的问题及其证据位置、影响和修正动作。 |

对会改变路线的题意分歧、基线验收中的关键疑点或主要结论缺少证据，优先安排未参与该方案生成的评委独立核验；交付前从评阅视角通读摘要、主图与结论。提供原始材料、实际产物和待核问题，不预置“应当认可”的结论。评审意见须由证据裁决，不因角色称谓直接采纳；修改后只复核受影响内容，不为例行通过项新增报告。

委派遵循用户与当前环境的协作规则，明确必要上下文、任务边界、产物及结束条件；允许并行写入时划清文件责任，避免覆盖他人修改。主 Agent 负责整合与最终核验，各职能使用同一份模型定义和结果来源。无法安排独立代理时由主 Agent 切换视角自查，如实说明核验方式，不冒充独立评审。任务结束确认子任务已完成，停止不再需要的后台工作。

## 必须守住的证据边界

1. 原始材料只读；清洗、聚合、筛选和模拟有可追溯理由。模拟与测试数据明确标识，不能混作观测数据。
2. 数值来自真实运行。检查单位、索引、边界、可行性与求解状态；不能用同一错误逻辑自证。优化最优性需要相应证据。
3. 验证符合实际使用场景：训练与测试隔离，决策只用当时可见信息，调参后的同一批数据不再冒充独立测试。
4. 比较注明对象、时间范围、代价与初终状态等关键条件。公平口径冲突时说明取舍；局部证据不能自动外推整体。
5. 论文数字、表图与实现对应。引用可追溯；官方规则、用户选择、工作假设与个人建议分别表达。

## 自主空间与停止条件

论证结构、模型组合、图型、配色和篇幅由问题、证据和当届规则决定。没有固定图数、公式数、模型族配额或强制期刊风格。只加载当前需要的参考；不为例行操作召集全套审查。

遇到反复失败，先复核假设、工具和目标再换路。候选路线无实质收益、证据不稳或占用交付时间时收缩；已验证的可交付版本保持可恢复。无法解决的关键缺口如实报告，并完成不受影响的工作。

交付时给出作品、主要判断及实际验证范围；只报告会影响使用的未解决问题。正文突出问题、发现与解释，完整核验记录留在支撑材料。
